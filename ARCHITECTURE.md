# Архитектура проекта

Стек: React 19, MobX, TypeScript, Vite, CSS Modules, Biome.

Эталонный пример фичи: [`src/App/Counter/`](src/App/Counter/).

## Пример структуры

```
src/
  main.tsx                  ← точка входа, вне дерева
  index.css                 ← глобальные стили (сброс, CSS-переменные)
  components/               ← глобальные переиспользуемые компоненты
    Button/
      Button.tsx
      Button.module.css
  App/                      ← корневая фича
    App.tsx
    App.module.css
    usePresenter.ts
    ChatStore.ts            ← общий стор для поддерева App
    ChatStoreContext.ts
    components/             ← переиспользуемые внутри App
      Avatar/
    MessageList/
      MessageList.tsx
      MessageList.module.css
      usePresenter.ts
    InputBox/
      InputBox.tsx
      InputBox.module.css
      usePresenter.ts
      useSmileInsert.ts     ← доп. хук, его импортирует только usePresenter
      SmilePicker/          ← нужен только InputBox
        SmilePicker.tsx
        SmilePicker.module.css
        usePresenter.ts
```

## 1. Фича

Фича — это папка с именем компонента в PascalCase:

| Файл                                                  | Назначение                       |
| ----------------------------------------------------- | -------------------------------- |
| `Feature.tsx`                                         | View: только разметка            |
| `Feature.module.css`                                  | Стили фичи                       |
| `usePresenter.ts`                                     | Вся логика фичи                  |
| `useXxx.ts`                                           | Хуки с отдельными частями логики |
| `XxxStore.ts`, `types.ts`, `utils.ts`, `constants.ts` | По необходимости                 |

**Любой файл — не больше 120 строк** (для `.ts`/`.tsx` проверяет Biome).
Это страховка, а не причина для разбиения: при правильном разделении логики по
смыслу в лимит не упираешься. Если файл упёрся в 120 строк — в нём смешаны
разные ответственности, их нужно разнести по хукам или дочерним фичам.

### View — `Feature.tsx`

- Всегда обёрнут в `observer`. Презентер выполняется во время рендера View и
  читает observable-поля; без `observer` компонент не подпишется на их
  изменения и не перерисуется.
- Принимает props и целиком передаёт их в `usePresenter(props)`, сам props не
  читает.
- Из хуков вызывает только `usePresenter`.
- **Можно:** `&&`, тернарники и `.map` по данным презентера; передавать
  значения и обработчики презентера в props детей; рендерить Provider контекста.
- **Нельзя:** другие хуки, вычисления, обработчики с логикой, сборка
  `className` по условиям — готовый класс возвращает презентер.

### Presenter — `usePresenter.ts`

- Вся логика: локальное состояние, обработчики, вычисления, эффекты, работа со
  сторами.
- Возвращает объект ровно с тем, что нужно View.
- Тип пропсов фичи объявляется и экспортируется здесь, View импортирует его
  через `import type`.
- Логика делится на хуки **по смыслу**: одна ответственность — один хук
  `useXxx.ts` рядом (загрузка данных, работа с вводом, обработка клавиатуры и
  т.п.). `usePresenter` собирает их и отдаёт View то, что ему нужно. Эти хуки
  импортирует только `usePresenter`, не View.

**Исключение:** если у компонента нет логики (он просто отрисовывает props),
`usePresenter` не нужен — View использует props напрямую, тип пропсов
объявляется в View. Пример: [`src/components/Button/`](src/components/Button/).

## 2. Дерево

Структура папок повторяет дерево компонентов.

- **Дочерняя фича**, которая нужна только одному родителю, лежит прямо в папке
  родителя: `InputBox/SmilePicker/`.
- **Переиспользуемый компонент** (нужен двум и более фичам) лежит в папке
  `components/` ближайшего общего предка всех мест использования:
  - `src/components/` — глобальные компоненты;
  - `<Feature>/components/` — компоненты для поддерева этой фичи. Такую папку
    можно создать на любом уровне дерева.
- Компонент в `components/` устроен как обычная фича и подчиняется тем же
  правилам, включая вложенность.
- Если компонент понадобился в другой ветке, он переезжает в `components/`
  ближайшего общего предка.

### Правила импорта

Переиспользование работает **только вниз** по дереву.

| Что                                                             | Кто может импортировать    |
| --------------------------------------------------------------- | -------------------------- |
| `usePresenter.ts`, доп. хуки, `*.module.css` фичи               | только файлы этой же фичи  |
| Дочерняя фича `X/Child/`                                        | только View фичи `X`       |
| `X/components/*`                                                | любой файл в поддереве `X` |
| Сторы, контексты, `types.ts`, `utils.ts`, `constants.ts` из `X` | любой файл в поддереве `X` |

- ✅ `InputBox/SmilePicker` → `src/components/Button`: глобальный компонент.
- ✅ `InputBox/SmilePicker` → `App/components/Avatar`: лежит в `components/`
  предка.
- ✅ `InputBox/SmilePicker` → `App/ChatStoreContext`: не-UI модуль предка.
- ❌ `MessageList` → `InputBox/SmilePicker`: чужая ветка. Нужен обоим —
  переносим в `App/components/`.
- ❌ `InputBox` → `MessageList`: соседняя фича.
- ❌ `SmilePicker` → `InputBox/usePresenter`: презентер родителя. Данные от
  родителя приходят через props.

## 3. MobX

- **Локальное состояние** фичи создаёт её `usePresenter`:
  `useState(() => new FeatureStore())`.
- **Общий стор** лежит в ближайшем общем предке всех фич, которые его
  используют, и передаётся вниз через props или контекст:
  - контекст объявлен в `XxxStoreContext.ts` в той же папке, что и стор;
  - Provider рендерит View предка, значение берёт из своего презентера;
  - потомки получают стор в своём `usePresenter` через `use(XxxStoreContext)`.
- В сторах используем `makeAutoObservable(this, {}, { autoBind: true })`,
  чтобы методы можно было передавать как обработчики.
- Презентер вызывается внутри `observer`-компонента, поэтому чтение
  observable-полей в презентере отслеживается.

## 4. Стили

- Только CSS Modules: один `Feature.module.css` на фичу, импортируется как
  `styles`.
- Имена классов — camelCase: `.inputField` → `styles.inputField`.
- Глобальные стили (сброс, CSS-переменные) — только в `src/index.css`.
- Стили фичи не используются другими фичами. Нужен общий вид — делаем
  компонент в `components/`.
